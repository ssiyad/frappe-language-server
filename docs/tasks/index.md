## Critical path

Nothing blocks anything else inside phase 3, so the order is a choice about
risk.

`013` is the only structural work left: a reverse occurrence index built during
the scan rather than an on-demand grep ([21](../specs/21-navigation.md)).

`012` publishes already. What remains of it is the part that needs to be *made*
quiet rather than kept quiet — teaching the absence checks about attributes a
controller assigns at runtime, which is what stands between 67 diagnostics on
correct `frappe` code and zero.

`010` holds only completion for hook keys and binding `doctype_js` scripts as
navigation targets. `018` needs workspace discovery and nothing else.

## Carried forward

Two gaps outlive the tasks that created them, both recorded here so they are not
rediscovered:

- **No `erpnext` bench.** Every performance number is measured on ~1/23 of the
  reference workload in [31](../specs/31-performance.md). The cache exists for a
  scale nothing here has run at.
- **`cargo xtask codegen` is a stub.** Three vendored tables — `Document`
  members, the hook registry, form events — were generated by hand from recipes
  recorded beside them. CI cannot see drift, and every omission found so far has
  surfaced as a false positive on correct code: `app_color`, then
  `doctype_list_js` and its family.
- **No benchmarks.** `cargo bench` has nothing to run; the budgets in
  [31](../specs/31-performance.md) are asserted by tests that skip without a
  bench, not by a suite that tracks them over time.
